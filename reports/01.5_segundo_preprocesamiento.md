## 1. Introducción

En esta etapa del proyecto, se realizó la transformación del dataset procesado con el objetivo de convertirlo en una representación completamente numérica, apta para la aplicación de modelos de regresión, dado que los algoritmos no entienden nuestro lenguaje, y jamás lo harán...

El dataset, ya parcialmente procesado, aún contenía variables categóricas en formato textual, incompatibles con los algoritmos de aprendizaje supervisado implementados. Esta fase, por tanto, no solo implicó limpieza, sino una reinterpretación del significado de los datos: una traducción desde el lenguaje humano hacia el lenguaje matemático.

---

## 2. Problema Detectado

Durante el primer intento de entrenamiento del modelo de regresión lineal, se presentó el siguiente error:

> *ValueError: could not convert string to float*

Este error evidenció que el dataset aún contenía valores no numéricos, lo que imposibilita su uso en modelos de regresión tradicionales.

Se identificaron como problemáticas las siguientes variables:

* `model`
* `cylinders`
* `title_status`
* `drive`
* `paint_color`
* `state`

Estas variables representan información relevante, pero en un formato no directamente utilizable.

---

## 3. Decisiones de Transformación

### 3.1 Eliminación de ambigüedad numérica

La variable `cylinders`, originalmente en formato textual, por ejemplo "8 cylinders", fue transformada a valores numéricos.

**Justificación:**
Esta variable representa una magnitud cuantitativa real. Convertirla permite preservar su significado físico y facilitar su uso por el modelo.

---

### 3.2 Codificación de variables categóricas (One-Hot Encoding)

Las variables categóricas de baja y media cardinalidad fueron transformadas mediante One-Hot Encoding.

**Variables afectadas:**

* `title_status`
* `drive`
* `paint_color`

La variable `state` fue eliminada previamente al proceso de codificación.

**Justificación:**

* Evitar la imposición de relaciones ordinales artificiales  
* Representar correctamente categorías independientes  
* Permitir al modelo interpretar cada categoría como una dimensión propia  
* Eliminar ruido geográfico irrelevante, dado que `state` representa estados de EE.UU. y el modelo se orienta a un contexto distinto (Chile)  

Se utilizó `drop_first=True` para evitar multicolinealidad.

---

### 3.3 Tratamiento de la variable `model`

La variable `model` presentó un desafío particular debido a su alta cardinalidad, ya que representa el modelo específico de vehiculo ingresado desde su fuente de origen.

#### Problema:

* Cientos o miles de valores únicos
* One-Hot Encoding generaría una explosión dimensional
* Alto riesgo de sobreajuste y degradación del rendimiento

#### Solución aplicada: Target Encoding

Cada modelo de vehículo fue reemplazado por el precio promedio asociado a dicho modelo.

Ejemplo conceptual:

```
tacoma → 18000  
civic → 12000  
camaro → 25000  
```

**Justificación:**

* Preserva la información predictiva
* Reduce la dimensionalidad
* Introduce conocimiento estadístico directo en el modelo

---

### 3.4 Manejo de valores nulos

Todos los valores faltantes fueron reemplazados por 0.

**Justificación:**

* Los modelos de sklearn no admiten valores NaN
* Se optó por una solución simple y consistente
* Se deja abierta la posibilidad de imputación más sofisticada en etapas futuras

---

### 3.5 Generación y almacenamiento del mapping de `model`

Se generó un archivo adicional:

```
model_encoding_map.csv
```

Este archivo contiene el mapeo entre cada modelo de vehículo y su valor numérico correspondiente (precio promedio).

**Justificación:**

* Permitir la reutilización del encoding en fase de inferencia
* Garantizar consistencia entre entrenamiento y uso del modelo
* Facilitar la interacción futura con usuarios


### 3.6 Normalización de variables numéricas

Se aplicó un proceso de normalización sobre las variables numéricas continuas mediante el uso de StandardScaler.

**Justificación:**

* Las variables del dataset presentan distintas escalas (por ejemplo, coordenadas geográficas, precios promedio por modelo, etc.)
* Estas diferencias pueden sesgar el aprendizaje de modelos lineales, otorgando mayor peso a variables con valores más grandes
* La normalización permite centrar los datos en una media de 0 y una desviación estándar de 1, mejorando la estabilidad del entrenamiento

**Criterio aplicado:**

* Se normalizaron únicamente variables numéricas continuas  
* No se normalizaron variables binarias (One-Hot Encoding), ya que su escala (0 y 1) ya es adecuada y significativa  

Este enfoque permite mantener la interpretabilidad de las variables categóricas mientras se mejora el rendimiento general del modelo.
---

## 4. Resultado Final

El dataset resultante (`vehicles_processed_nums.csv`) cumple con las siguientes condiciones:

* 100% numérico
* Libre de valores nulos
* Dimensionalidad controlada
* Compatible con modelos de regresión

Este dataset se convierte así en la base común para el entrenamiento de todos los modelos, asegurando una comparación justa entre ellos. Contando con 349623 registros y 92 columnas en total, un aumento de la cardinalidad no significativo para el entrenamiento de las técnicas.
